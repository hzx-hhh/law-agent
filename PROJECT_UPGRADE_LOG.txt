AI 法律案件辅助分析平台
项目升级与开发记录
记录时间：2026-10-27

一、项目原始状态

项目最初是一个房屋租赁纠纷法律文书 Agent MVP，技术栈为 FastAPI、原生 HTML/JavaScript、本地 laws_db.json 和 DeepSeek 兼容接口。

初始工作流：
1. 用户输入案件事实和诉求。
2. 后端使用关键词匹配检索本地法律资料。
3. 后端拼接 Prompt 调用大语言模型。
4. 模型返回 laws、issues、draft 三个字段。
5. 前端展示法条、争点和可编辑诉讼方案。

初始主要问题：
- API Key 硬编码在 main.py。
- CORS 全开放。
- 没有鉴权、租户、限流、幂等和审计。
- 检索只是关键词包含匹配，不能称为完整 RAG。
- 法律资料很少，案例带有虚拟案号。
- 缺少引用原文、版本、生效日期和证据 ID。
- 所有模型异常都被当作正常结果回退。
- 没有自动化测试、评测集、真实 bad case 和监控。
- 没有案件保存、人工审核和文档导入能力。

二、第一阶段：从 MVP 升级为可审计原型

1. 移除硬编码密钥

- 删除 main.py 中的硬编码 API Key。
- 改用 LLM_API_KEY 或 DEEPSEEK_API_KEY 环境变量。
- 增加 .env.example。
- README 增加密钥轮换和泄露处理说明。
- 扫描项目确认没有残留硬编码 sk- 密钥。

2. 增强 API 响应协议

新增字段：
- request_id
- status
- risk_level
- citations
- missing_evidence
- next_actions
- corpus_version
- model
- structured_issues

状态包括：
- SUCCESS：模型分析成功。
- DEGRADED：模型不可用，使用本地规则回退。
- NEEDS_MORE_INFO：案情信息不足，要求补充事实。
- MODEL_OUTPUT_INVALID：模型输出没有通过结构校验。

3. 增加证据引用

法律资料现在返回：
- evidence_id
- 法条或案例类型
- 标题
- 条文内容或裁判规则摘要
- retrieval_score
- corpus_version
- synthetic 标记

模型只能在检索上下文中归纳，法律引用由系统证据包提供，避免模型凭空生成法条或案号。

4. 增加请求追踪和健康检查

新增：
- X-Request-ID 响应头。
- X-Response-Time-Ms 响应头。
- GET /health/live。
- GET /health/ready。
- 结构化日志。

5. 增强输入和模型输出校验

- 限制案件描述长度。
- 限制诉求数量和单条诉求长度。
- 校验模型 JSON 是否合法。
- 校验 issues 和 draft 字段是否存在。
- 非法 JSON 不再直接返回给前端。

6. 改进本地检索

- 支持中文二元词切分。
- 返回可解释检索分数。
- 法条和案例分别排序。
- 支持无结果时的默认资料回退。

五、第四阶段：收敛主线和提升可信度

1. 真正接入 BM25

之前的检索只是关键词重叠。之后接入 rank_bm25.BM25Okapi，并保留：
- 中文二元词切分。
- embedding 余弦相似度。
- 标题加权。
- rerank 综合分数。

新增 retrieval.py 和 BM25 回归测试。

2. 修复真实 BM25 引入后的分数边界 Bug

失败现象：
启用 rank_bm25 后，重排分数超过 1，Citation 的 Pydantic ge=0、le=1 校验失败，信息不足请求返回 500。

根因：
算法分数没有统一归一化，调用层假设所有分数已经在 0 到 1 之间。

解决：
所有 retrieval_score 统一 bounded 到 [0,1]。

验证：
所有测试和离线评测重新通过。

3. 收紧认证

新增 REQUIRE_AUTH 和 ALLOW_DEMO_TOKEN 配置。

没有认证时可以在本地开发运行；生产配置要求 Bearer Token，并关闭演示 Token。

4. 跨租户越权测试

测试场景：
租户 A 创建分析，租户 B 使用同一个 analysis_id 导出。

预期：
返回 404，不暴露资源存在性。

结果：
通过。

5. 法律资料来源和版本

- version。

legal_corpus_validate.py 校验法律资料完整性。

当前结果：CORPUS_VALID。

八、面试推荐项目定位

推荐表述：

我从一个房屋租赁纠纷法律文书 MVP 开始，逐步补充了 BM25 和可选 embedding 检索、证据引用、失败降级、PII 脱敏、租户隔离、人工审核、文档导入、自动化测试、故障注入和可观测性。当前版本是可以运行的工程化原型。对于 PostgreSQL/pgvector、Redis 集群、OIDC 和真实 OCR，我完成了可切换适配器和本地回退，但没有把未在真实基础设施中验证的功能包装成已经生产上线。

重点案例：
一次接入真实 BM25 后，分数超过下游 Citation Schema 上限，导致信息不足请求 500。我通过 request_id 和测试定位到是分数归一化边界问题，统一把检索分数裁剪到 [0,1]，增加回归测试，最终 17 个测试全部通过。
