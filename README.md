# AI 法律案件辅助分析平台

当前版本在原 MVP 基础上增加了可审计输出、证据引用、降级状态、请求追踪、输入校验和离线评测样例。系统定位是法律辅助工具，不能替代律师意见。

## 快速启动

```bash
python -m venv .venv
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
uvicorn main:app --reload
```

如需调用模型，请在当前终端设置 `LLM_API_KEY`；未配置时接口会自动进入 `DEGRADED` 本地回退模式，方便测试和演示。

## API 状态

- `GET /health/live`：进程存活检查
- `GET /health/ready`：法律资料库就绪检查
- `POST /api/analyze`：案件分析。响应包含 `status`、`request_id`、`citations`、`missing_evidence`、`next_actions` 和 `corpus_version`。
- `SUCCESS`：模型分析成功；`DEGRADED`：模型不可用，返回本地规则回退；`NEEDS_MORE_INFO`：案情过短，需要补充事实；`MODEL_OUTPUT_INVALID`：模型输出未通过 JSON 校验。

## 项目背景与解决的问题

本项目聚焦于“房屋租赁纠纷”这一高频民事法律场景，面向押金退还、房屋损坏、提前退租等常见争议类型，尝试构建一个可演示、可扩展的 AI 法律文书辅助系统原型。在实际法律服务过程中，律师或法务人员往往需要先从聊天记录、合同文本和当事人陈述中整理出零散案情，再查找对应法条、筛选类案规则，最后形成初步诉讼方案。这一流程具有明显的重复性，且对资料归纳效率要求较高。

传统做法存在两个主要问题。第一，案件事实通常分散在多轮沟通中，人工梳理耗时较长。第二，法条检索与类案比对需要依赖经验和数据库查询，前期准备工作较重，不利于快速形成初步判断。本项目希望通过“本地法律资料检索 + 大语言模型生成”的方式，为房屋租赁纠纷场景提供一个轻量级辅助工具，帮助用户更快完成从案情输入到诉讼方案初稿输出的流程。

## 系统架构与逻辑

本系统采用前后端分离的轻量化设计。前端使用原生 HTML 与 JavaScript 实现页面交互，并通过 Tailwind CSS CDN 完成样式美化，优点是结构简单、无需复杂工程化配置，适合课程作业中的快速演示与本地部署。后端使用 FastAPI 构建接口服务，负责接收用户输入、读取本地法律知识库、组装提示词并调用大语言模型，再将结构化结果返回给前端页面展示。

从职责划分上看，前端主要承担信息采集与结果展示功能。用户在页面左侧输入“案件事实”和“当事人诉求”，点击按钮后，浏览器通过 `Fetch API` 向本地后端发送请求。后端则负责业务逻辑处理，包括读取 `laws_db.json`、根据关键词进行简易本地检索、构建系统提示词与上下文、调用 DeepSeek 大语言模型，并将分析结果整理为统一的 JSON 格式返回。前端拿到返回结果后，再将其渲染为依据卡片、争点卡片和可编辑的诉讼方案文本区域。

### 核心工作流

系统的核心工作流可以概括为以下几个步骤：

1. 用户在前端页面中输入案件事实与当事人诉求。
2. 前端通过 `POST /api/analyze` 将数据提交到 FastAPI 后端。
3. 后端读取本地法律资料库 `laws_db.json`，从中检索与当前纠纷相关的法条与类案摘要。
4. 后端将用户输入信息和本地检索到的法律上下文共同拼接成 Prompt。
5. 后端调用 DeepSeek 提供的兼容 OpenAI SDK 接口，请求大语言模型输出结构化分析结果。
6. 模型返回包含 `laws`、`issues`、`draft` 的 JSON 数据。
7. 前端将结果展示在右侧工作区，其中诉讼方案初稿支持用户继续编辑和导出。

这一流程体现了一个典型的“检索增强生成”思路，即先通过本地知识库补充法律上下文，再利用大语言模型完成归纳、分析与文书草拟，从而提升输出结果与具体法律场景的相关性。

## 本地部署与运行测试说明

本项目适合在本地直接运行，所需环境较为简单，核心依赖包括 FastAPI、Uvicorn、OpenAI SDK 与 Pydantic。由于前端页面采用单文件 `index.html` 方案，不需要额外安装前端构建工具，只需启动后端接口并直接打开网页即可完成测试。

### 1. 安装 Python 依赖

在项目根目录下打开命令行，执行以下命令安装依赖：

```bash
pip install -r requirements.txt
```

如果本地存在多个 Python 版本，也可以根据环境使用：

```bash
python -m pip install -r requirements.txt
```

### 2. 启动后端服务

依赖安装完成后，在项目根目录继续执行以下命令启动 FastAPI 服务：

```bash
uvicorn main:app --reload
```

正常情况下，终端会显示本地服务启动信息，默认监听地址为：

```text
http://127.0.0.1:8000
```

此时可以在浏览器访问上述地址，确认后端健康检查接口已正常启动。

### 3. 打开前端页面

后端启动后，直接在项目根目录中双击打开 `index.html` 文件即可。由于页面使用原生 HTML 和 JavaScript 编写，不依赖任何前端构建工具，因此可以直接在浏览器中运行。

页面打开后，用户可在左侧输入：

- 案件事实
- 当事人诉求

点击“生成诉讼方案”按钮后，系统会向本地后端发送请求，并在右侧工作区展示分析结果，包括相关法条与类案、有利与不利依据，以及可编辑的诉讼方案初稿文本。

### 4. 运行测试建议

为了验证系统功能是否正常，可以使用如下测试输入进行演示：

- 案件事实：承租人签订一年租赁合同，居住四个月后因工作调动提前退租。出租人认为承租人存在违约，并以墙面污损和家具损坏为由拒绝退还全部押金。
- 当事人诉求：要求返还押金，确认部分扣款无事实和法律依据。

若系统运行正常，前端页面右侧将展示模型分析出的相关法律依据、案件争点以及一份可以继续编辑的诉讼方案初稿。该结果说明前后端联通、本地检索流程和大模型调用逻辑均已生效。

## 未来的扩展性说明

本系统在设计上保持了较强的松耦合特征。前端页面主要负责输入与展示，不直接依赖具体法律领域知识；后端接口则将“检索数据源”和“大模型生成逻辑”分开处理，因此整体结构具备较好的可迁移性。当前项目虽然聚焦于房屋租赁纠纷，但其核心框架并不局限于这一主题。

未来如果希望扩展到“劳动仲裁”“合同违约”“民间借贷”等其他法律场景，最直接的方式就是替换本地法律知识库 `laws_db.json` 中的数据内容。例如，可以将其中的法条与案例由租赁纠纷相关材料改为劳动法、合同法或其他民事争议类型的资料，而前端页面、后端接口、模型调用逻辑基本都可以保持不变。也就是说，系统的领域切换主要发生在“知识库内容层”，而不是“程序框架层”。

在进一步开发中，还可以从以下几个方向继续扩展：

- 将当前基于关键词的本地检索升级为向量检索，以提升法条与案例召回的准确性。
- 将单一的 `laws_db.json` 扩展为多个专题知识库，支持根据案件类型自动选择不同法律领域的数据源。
- 增加文书导出能力，例如导出为正式的起诉状、答辩状或法律意见书格式。
- 增加用户登录、案件保存和历史记录管理模块，使系统从演示原型逐步演进为可持续使用的法律辅助工具。

总体来看，本项目不仅完成了房屋租赁纠纷场景下的 MVP 演示，也验证了一种具有延展性的系统思路：通过统一的交互界面、可替换的知识库和可扩展的大模型调用模块，为不同法律业务场景提供通用的智能文书辅助能力。

## 第三阶段企业化骨架

当前版本已经提供 SQLite/PostgreSQL 持久化模型、JWT/OIDC 接入点、租户隔离字段、幂等键、租户级限流、Prometheus 指标、文档上传抽取、审核记录和文本报告导出。`docker-compose.yml` 使用 pgvector PostgreSQL 镜像，可作为后续向量检索的基础设施。

```bash
docker compose up --build
```

生产化下一步应配置真实企业 SSO/OIDC、Redis、PostgreSQL/pgvector 和隔离的 OCR 服务，并完成多实例压测与真实法律资料复核。
